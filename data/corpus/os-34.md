程序查询方式下 CPU 启动设备后并不离开，而是反复读取控制器的状态寄存器，用测试指令判断就绪位是否置 1；未就绪就跳回再测，形成忙等待，直到就绪才执行一条输入指令把数据寄存器中的字节送入内存。设 CPU 主频 1GHz，一次轮询由读状态寄存器、测试、条件跳转三条指令构成，共约 200 个时钟周期，即 0.2 微秒；某设备每产生一个字节需被轮询 100 次才就绪，则等待耗去 20 微秒，再加 0.1 微秒的传送指令，CPU 为一个字节付出 20.1 微秒。若该设备速率为 50KB/s，即每 20 微秒到达一个字节，则 CPU 占用率为 20.1 除以 20，超过 100%，说明查询方式在该速率下已无法支撑，CPU 被完全占满。

中断驱动方式把等待交给硬件：CPU 填好命令寄存器后启动设备即可返回原程序，设备每完成一个字节的传送便发一次中断请求，CPU 响应后保存现场、进入中断服务程序取走数据并再次启动设备，然后恢复现场。传送 n 个字节就产生 n 次中断，CPU 介入次数等于字节数。设每次中断的响应、保存现场、服务与恢复共 2 微秒，传送 1KB 数据即 1024 字节，CPU 用于中断的时间为 1024 乘以 2 微秒等于 2048 微秒，约 2.05 毫秒；若设备速率仍为 50KB/s，传完 1KB 需 1024 乘以 20 微秒等于 20.48 毫秒，CPU 占用率约 10%。相比查询方式的 100%，中断方式把 CPU 从等待中解放出来，但每字节一次中断的开销仍随数据量线性增长。

DMA 方式以数据块为单位，CPU 只在传送开始前把内存起始地址、字节计数和传送方向写入 DMA 控制器的寄存器并启动它，以及在一整块传完后处理一次结束中断，块内每个字节的搬运由 DMA 控制器直接在主存与设备之间完成，不经过 CPU。设块大小为 4KB，传送 1MB 数据需 1MB 除以 4KB 等于 256 个块；若每块的预处理与结束中断合计 3 微秒，CPU 总开销为 256 乘以 3 微秒等于 768 微秒，仅约 0.77 毫秒。同样 1MB 数据若用中断方式，需 1048576 次中断，按每次 2 微秒计为 2097152 微秒，约 2.1 秒，是 DMA 的 2731 倍。即使只传 1KB，中断方式要 1024 次介入，DMA 按 4KB 成块只需 1 个块、两次介入。

通道是能执行通道程序的专用处理器，通道程序由一连串通道指令组成并存放于主存，每条通道指令可控制一台设备传送若干不连续的块。CPU 只需执行一条启动 I/O 指令并给出通道程序首地址，通道便自行取指、译码、控制设备，把 1MB 数据按通道程序中的 256 条读命令逐块搬入主存，全部完成后才用一次中断报告，CPU 介入仅启动与结束两次。与 DMA 的层次差别在于：DMA 控制器只能执行 CPU 预置好的一次一维块传送，每换一个块就要 CPU 重新初始化；通道拥有自己的指令系统和程序计数器，能连续执行多条命令、同时管理多台设备，因而不必每块都打扰 CPU。代价是通道硬件更复杂，通常只出现在大型机与服务器上。

把四种方式按四个维度并排比较。传送单位上，查询与中断都以字节或字为单位，DMA 以数据块为单位，通道以一组块为单位。CPU 介入频率上，查询是全程忙等、每次传送都介入；中断是每字节一次；DMA 是每块两次，即预处理与结束中断；通道是每个通道程序两次。硬件成本上，查询只需状态寄存器，最便宜；中断要增加中断机构与优先级仲裁；DMA 要专用控制器与总线仲裁逻辑；通道相当于增加一台小型处理器，最贵。适用设备上，查询适合低速或 CPU 无事可做的场合，中断适合键盘、串口等低速字符设备，DMA 适合磁盘、网卡等高速块设备，通道适合连接大量高速设备的大型机。

设某设备速率 2MB/s，CPU 主频 1GHz，每次中断开销 2 微秒，判断中断方式能否胜任。设备每秒产生 2 乘以 10 的 6 次方个字节，若每字节中断一次，每秒中断 200 万次，CPU 花在中断上的时间为 2000000 乘以 2 微秒等于 4 秒，即每 1 秒要付出 4 秒 CPU 时间，占用率 400%，远超 100%，中断方式不可行。即便每次中断传一个 4 字节字，中断次数降为每秒 50 万次，仍需 1 秒 CPU 时间，占用率恰为 100%，系统没有余量。改用 DMA：块大小 4KB，每秒 2MB 除以 4KB 等于 512 块，每块按 3 微秒计共 1536 微秒，占用率约 0.15%，完全可行。可见高速设备必须依靠 DMA 或通道。

DMA 与通道都要同 CPU 争用主存总线。DMA 常用周期挪用，即每传一个字节或字就申请占用一个存储周期，把 CPU 推迟一个周期；设存储周期 0.5 微秒、每次挪用传 4 字节，2MB/s 的设备每秒需 50 万次挪用，占去 0.25 秒总线时间，即 25%，CPU 访存被拖慢两成多。若设备成组传送，可采用交替访问，把存储周期分时交替给 CPU 与 DMA，两者不冲突，但 CPU 可用带宽减半。通道方式下通道本身要读通道程序、写数据，争用更重，需由通道控制器统一排队；多个通道并行工作时，主存带宽往往成为真正的瓶颈。
