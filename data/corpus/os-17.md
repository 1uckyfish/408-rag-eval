优先级决定就绪进程谁先占用处理机，依据有二。一是进程性质：系统进程负责中断处理、内存管理与设备驱动，优先级应高于普通用户进程。二是 CPU 与 I/O 的使用比例：CPU 时间占比越低，进程请求 I/O 越频繁，优先运行它就能尽快发出 I/O 请求，使设备与 CPU 同时忙碌；CPU 繁忙型进程若给高优先级，会长时间占机而让设备闲置。故占比越低，优先级应越高。例如三个进程的 CPU 占比为 90%、50%、15%，应依次给低、中、高优先级：占比 15% 者很快算完一段转入 I/O，CPU 随即运行占比 90% 者。

静态优先级在创建时一次确定，运行期间不变，可按进程类型指定。它计算简单、开销小，但低优先级进程可能长期得不到处理机而饥饿，且难以预估其 CPU 与 I/O 特性。动态优先级在运行中调整，依据已占用 CPU 时间与等待时间重算优先数：新进程给较高值，占用 CPU 过久者降低，等待过久者提高。动态方案开销较大，但能适应行为变化，兼顾效率与公平。

动态优先数由静态基准、已用 CPU 时间与等待时间三项合成：优先数 = 静态优先数 + 等待时间项 − 已用 CPU 时间项，值越大优先级越高；按 Unix 惯例取小值优先时等价写成 优先数 = nice + cpuTime − waitTime。cpuTime 为已获得的处理机时间，该项使占用 CPU 越多优先数越不利，抑制计算型进程霸机；waitTime 为就绪队列中的等待时间，该项使等待越久越有利，保证最终被调度。两项方向相反、互相制衡，故同一公式兼顾公平与响应。每次调度前重算，取最优者运行。

高响应比优先用比值衡量等待与执行：响应比 =（等待时间 + 要求服务时间）/ 要求服务时间。短作业比值升得快，长作业等得够久也会超过新来的短作业，故不会饥饿。设 J1 于 0 时刻到达需 40ms，J2 于 5ms 到达需 60ms，J3 于 35ms 到达需 10ms。0 时刻 J1 先运行至 40ms。40ms 时 J2 已等 35ms，响应比 95/60 约 1.58；J3 已等 5ms，响应比 15/10 等于 1.50，故 J2 运行 40～100ms，J3 运行 100～110ms。周转时间依次为 40ms、95ms、75ms，平均 70ms。

多级反馈队列设多个就绪队列，优先级从高到低递减，时间片从短到长递增。新进程进最高级队列末尾；用完本级时间片未完成则降一级到队尾；仅当高一级队列为空才调度低一级，短进程很快完成，长进程逐级下移。设两级：Q1 时间片 10ms 轮转，Q2 短进程优先。A 需 30ms、B 需 20ms，均在 0 时刻到达。时间轴：0～10ms A 未完成，降入 Q2 剩 20ms；10～20ms B 未完成，降入 Q2 剩 10ms；Q1 已空，Q2 中 B 剩 10ms 短于 A 的 20ms，20～30ms B 完成；30～50ms A 完成。周转时间 A 50ms、B 30ms，平均 40ms。

单道时 CPU 与 I/O 串行，发出 I/O 请求后 CPU 空等；多道下，一个进程等 I/O 时处理机可切换给另一进程，计算与传输重叠，总时间小于各自时间之和。设 P1 需计算 60ms、I/O 80ms、计算 20ms；P2 在 5ms 到达，需计算 120ms、I/O 40ms、计算 40ms；单 CPU，I/O 可与 CPU 并行，不计切换。时间轴：0～60ms P1 计算；60～140ms P1 做 I/O，同时 60～180ms P2 计算；140ms P1 的 I/O 结束，等 CPU；180～200ms P1 完成第二次计算；180～220ms P2 做 I/O；220～260ms P2 完成第二次计算。全部完成 260ms，小于串行的 360ms。

评价调度算法有四个指标：吞吐量是单位时间完成的作业数；周转时间是作业从提交到完成的全部时间；响应时间是交互作业首次得到响应的时间；公平性指各进程获得处理机的机会是否均等。四者互相冲突：提高吞吐量要减少切换、让长作业连续运行，拉长短作业的响应；缩短响应要频繁切换，切换开销又降低吞吐量；强调公平可能牺牲效率。批处理系统重吞吐量与周转时间，常用短作业优先、最高响应比优先；分时系统重响应时间，采用时间片轮转与多级反馈队列。

饥饿指某进程因优先级偏低，在可运行状态下长期得不到处理机。短作业优先、静态优先级和多级反馈队列都可能引起饥饿：短作业不断到达，长作业便一直排不上。老化是通用解法：让等待时间参与优先级计算，进程每等待一段时间优先级就提高一级，越等越高，直到超过新到进程而获得处理机，运行后回落。它代价很小却消除了无限等待，最高响应比优先也体现了这一思想。
