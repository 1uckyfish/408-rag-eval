有界缓冲有 n 个槽位，buffer 为环形数组，in 指向空槽，out 指向产品。设 empty 为空槽数，初值 n；full 为产品数，初值 0；mutex 保护 buffer、in、out，初值 1。生产者：生产产品；P(empty)；P(mutex)；buffer[in] = 产品；in = (in+1) % n；V(mutex)；V(full)。消费者：P(full)；P(mutex)；取走 buffer[out]；out = (out+1) % n；V(mutex)；V(empty)；消费。

两个 P 的次序不能颠倒。生产者若先 P(mutex) 再 P(empty)，缓冲满时它占着锁等空槽；消费者取产品要先 P(mutex)，锁在生产者手里，无法取走并 V(empty)，双方互等，死锁。消费者同理必须先 P(full) 再 P(mutex)，否则空缓冲时持锁等产品。两个 V 的次序无所谓，V 不会阻塞，先 V(mutex) 再 V(full) 更常见。记法：先申请会阻塞的资源信号量，再申请锁；先释放锁，再唤醒别人。

读者优先设 readcount（初值 0）、count_mutex（初值 1，保护计数）、write_mutex（初值 1，读写互斥）。读者进入：P(count_mutex)；readcount++；若为 1 则 P(write_mutex)；V(count_mutex)；读。读者退出：P(count_mutex)；readcount--；若为 0 则 V(write_mutex)；V(count_mutex)。写者：P(write_mutex)；写；V(write_mutex)。第一个读者替全体加写锁，最后一个读者替全体释放，中间读者只改计数，故多个读者同时读，写者与所有人互斥。

读者优先会让写者饥饿：读者接连到达时 readcount 恒大于 0，write_mutex 一直被占，写者等不到。写者优先加闸门 read_gate（初值 1），并用 writecount、mutex2 统计写者。读者进入先 P(read_gate) 再立即 V(read_gate)。写者到达：P(mutex2)；writecount++；若为第一个写者则 P(read_gate) 关闸；V(mutex2)；P(write_mutex)；写；V(write_mutex)；P(mutex2)；writecount--；若为最后一个写者则 V(read_gate) 开闸；V(mutex2)。第一个写者关闸后新读者被挡住，已在读的读者退完，写者进入；写者全走才开闸。

n 个哲学家、n 根筷子，chopstick[i] 初值 1，进餐需同时持第 i 与第 (i+1) mod n 根。方案一限制并发：room 初值 n−1，取筷前 P(room)，取左、取右，吃，放左、放右，V(room)。至多 n−1 人竞争；若僵持，n−1 人各持一根恰余一根，余根旁必有人已持另一根，可取走进食。方案二定序：奇数号先左后右，偶数号先右后左，申请方向不成环，破坏循环等待。方案三用 AND 型信号量：Swait 一次申请两根，都空闲才分配，否则全不给；吃完 Ssignal 一次释放两根。

三个问题同构：持有部分资源后又申请更多。生产者持空槽等 mutex，读者持 count_mutex 等 write_mutex，哲学家持一根等第二根，都是占有并等待。通用解法是资源有序分配：资源统一编号，进程只能按编号递增申请，已持编号恒小于将申请编号，就不会出现互等对方低号资源的环。哲学家方案二即其特例，奇数先小后大、偶数先大后小，等价于全局同一顺序取筷。代价是次序受约束、利用率下降，抢不到高号资源者可能饥饿，适合资源种类稳定的系统。

把 full 的 P 放到 mutex 之后，即 P(mutex)；P(full)；取产品；V(mutex)；V(empty)，会死锁。设 n = 2，初值 empty = 2、full = 0、mutex = 1。消费者 C 先 P(mutex)（mutex = 0），再 P(full)（full = −1）阻塞，仍占锁。生产者 P(empty)（empty = 1），再 P(mutex)（mutex = −1）也阻塞。C 等 full 变正，只有生产者放入产品才会 V(full)；生产者等 mutex，只有 C 取完才会 V(mutex)，互等死锁。更多消费者会继续消耗 empty 后在 mutex 排队。正确写法是 P(full) 在前，拿锁前先确认有产品。

三种解法可对照检查。先看共享变量：buffer、in、out 归 mutex 管，readcount 归 count_mutex 管，筷子各有信号量，被多进程读写的变量都要有互斥手段。再看信号量角色：empty、full 是计数，mutex、count_mutex 是锁，write_mutex 兼作全体读者的读权限。然后查 P 序：先申请会阻塞的资源信号量，再申请锁；查 V 序：先放锁再唤醒。最后问是否存在持资源后无限等待另一资源，若有就改用有序分配或限制并发。
