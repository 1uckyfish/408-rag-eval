信号量的值 S = 当前可用资源数 − 在该信号量上等待的进程数。S 大于 0 时值即可分配资源数，无人等待；S 等于 0 时资源恰好分完；S 小于 0 时可用数为 0，绝对值是等待队列长度。例一：4 台打印机、初值 4，6 个进程申请，前 4 个把值减到 0 后进入，后 2 个减到 −2 并阻塞，即可用 0 台、等待 2 个。例二：互斥信号量初值 1，3 个进程竞争，第一个进入后值为 0，另两个减到 −2，等待 2 个。例三：同步信号量初值 0，3 个消费者先后 P 后值为 −3，都等待；生产者 V 三次，值回 0 并依次唤醒。V 把 −2 加到 −1 只唤醒一个，该进程已算获得资源，故剩 1 个等待。

P、V 必须原子，因为改值与据此阻塞或唤醒之间若可切换，判断会基于过期值。设 S = 1，P 写成普通语句 S = S − 1；if (S < 0) 阻塞。A 读到 1 未写回即被切换，B 也读到 1，两者都写 0 且都判断 0 ≥ 0，同时进入临界区，互斥失效。S = 0 时 A、B 都读到 0、都写 −1 并阻塞，队列只登记一个，后一个 V 只唤醒一个，另一个永远醒不来。用关中断、TestAndSet 或内核原语把整段 P、V 封成临界区，才能保证值与队列一致。

初值只问一句：信号量代表什么，一开始有多少。代表锁，初值 1；代表资源剩余量，初值为初始可用数；代表事件尚未发生，初值 0。互斥锁 mutex 初值 1。生产者-消费者中 empty 初值 n、full 初值 0、mutex 初值 1。哲学家每根筷子初值 1，若加 room 限流则初值 n−1。读者-写者中 write_mutex 与 count_mutex 初值均为 1，readcount 是普通整型、初值 0，不是信号量。常见错误是把 full 初值写成 n，或把 readcount 当信号量加减，前者让消费者以为已有 n 个产品，后者混淆计数与互斥。

管程把共享数据和对它的操作封装在一起，由四部分组成：局部于管程的共享数据结构；一组操作过程，外部只能通过这些过程访问数据；初始化代码，在管程建立时执行一次；条件变量，每个带一个等待队列。语义有两条：任一时刻至多一个进程在管程内执行，互斥由编译程序或运行时自动保证，程序员不必再写 P、V；进程在条件变量上等待时必须让出管程，否则其他进程无法进入，也就无法改变条件。条件变量没有值，不能加减，只能 wait 和 signal。

条件变量与信号量的区别有四点。其一，信号量有整数值，V 在无人等待时把值加 1，许可被保存，后到的 P 可以立即通过；条件变量的 signal 没有记忆，无人等待时什么也不发生，许可丢失。其二，P 只决定是否阻塞，而管程中的 wait 必须释放管程的互斥权，否则被唤醒者也进不来。其三，signal 只唤醒一个等待者，不改变计数值；V 先加 1 再决定是否唤醒。其四，条件变量不能脱离管程单独使用，它只解决管程内等什么，互斥由管程负责；信号量既能互斥又能同步。因此不能用条件变量实现互斥，也不能指望在管程外 signal 生效。

用管程实现有界缓冲：数据为 buffer、count、in、out，条件变量 notFull 与 notEmpty。put(x)：当 count == n 时 wait(notFull)；放入 buffer[in]，in 前移，count++；signal(notEmpty)。get()：当 count == 0 时 wait(notEmpty)；取 buffer[out]，out 前移，count--；signal(notFull)；返回。管程已保证 put 与 get 互斥，无需 mutex，count 的加减天然安全。放入后唤醒消费者，取出后唤醒生产者，两个条件变量各管一个方向，不能合并，否则被唤醒者可能发现条件不满足。

管程中判断条件要用 while 而非 if，因为被 signal 唤醒不代表条件仍成立。Mesa 语义下 signal 者继续持管程，被唤醒者只是移到入口队列，要重新竞争，期间条件可能被第三者破坏。设容量 1，C1、C2 都因 count == 0 在 notEmpty 等待；生产者放入 1 个并 signal 唤醒 C1；C1 未进入时 C3 先进入，见 count == 1 便取走，count 变 0；C1 进入后若用 if 已通过检查，直接取空，甚至使 count 变负。用 while 则重新检查并再次 wait。多个生产者被 notFull 唤醒时同理，可能只剩一个空位。

把易错点收成检查表。第一，确认信号量代表资源还是事件：代表资源时初值为初始数量，代表尚未发生时初值为 0，代表锁时初值为 1。第二，看到负数不要慌，绝对值是等待数，配合可用数为 0 一起读。第三，凡是在持有锁时等待另一个可能被同组进程释放的信号量，都要检查是否成环。第四，管程内不再需要 mutex，条件变量上必须用 while，signal 无人等待时会丢失。第五，不要把 V 当成通知到处撒，多 V 会使信号量虚增，破坏互斥。按这五条逐行核对，大多数错用都能定位。
