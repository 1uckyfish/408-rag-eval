I/O 软件通常分为四个层次，从上层到下层依次是用户层 I/O 软件、设备独立性软件、设备驱动程序、中断处理程序。用户层 I/O 软件是用户进程直接调用的库函数和系统调用接口，它把请求转换为系统调用。设备独立性软件负责与设备无关的公共操作，如缓冲管理、差错控制、设备分配和逻辑设备名到物理设备名的映射。设备驱动程序直接与设备控制器打交道，把抽象命令翻译成设备能识别的操作。中断处理程序在设备完成操作后响应中断，完成状态检查和善后处理。

设备独立性是指用户程序使用逻辑设备名，而不必关心实际使用的是哪台设备，系统把逻辑设备名映射为物理设备名。这样程序可以适应设备的更换，一台设备出现故障时可以把作业转到同类设备上运行，提高了适应性和设备利用率。实现映射的数据结构是逻辑设备表，每个表项记录逻辑设备名、物理设备名和驱动程序入口地址。进程用逻辑设备名请求 I/O 时，系统查表找到对应的物理设备和驱动程序，再调用驱动程序完成实际操作。

设备驱动程序是 I/O 系统中直接与硬件相关的部分，职责是把抽象的 I/O 请求转换成具体的设备操作序列。驱动程序了解设备的寄存器设置、命令格式、时序和状态位含义，负责启动设备、设置工作方式、传送数据并检查结果。它向上一层提供一组标准接口，包括打开、关闭、读、写和控制等操作，接口参数是逻辑意义上的块号或字节数，而不是具体的寄存器值。设备驱动程序与设备无关软件的分界在于是否依赖具体硬件。

中断处理程序位于 I/O 软件的最底层，与硬件联系最紧密。当设备完成一次操作或发生错误时，控制器向 CPU 发出中断请求，CPU 响应后转入中断处理程序。它首先保存被中断进程的现场，然后读取设备的状态寄存器判断中断原因，若是正常完成则唤醒等待该 I/O 的进程，若是出错则设置错误标志并通知上层。处理完毕恢复现场，返回被中断的程序。中断处理程序只做与硬件密切相关的最低工作，其余留给驱动程序。

设备分配的任务是把设备、控制器和通道分配给进程。系统为每类资源建立控制表：设备控制表记录设备类型、状态、指向控制器的指针和等待队列；控制器控制表记录控制器状态和所连接通道的指针；通道控制表记录通道状态和等待队列；系统设备表是全局表，记录所有设备的情况，每个表项指向相应设备的设备控制表。分配时按系统设备表、设备控制表、控制器控制表、通道控制表的顺序逐级检查，设备、控制器与通道都可用才能分配成功。

设备分配有静态和动态两种策略。静态分配在作业开始前一次性分配所需全部设备，作业结束后才归还，实现简单，不会出现死锁，但设备利用率低。动态分配在作业执行中按需申请，利用率高，但可能出现死锁：一个进程占有了设备等待控制器，另一个进程占有了控制器等待设备，形成循环等待。为避免死锁，可采用资源有序分配法，规定进程按设备、控制器、通道的顺序申请。对独占设备独占分配，对共享设备允许同时访问，虚拟设备则借助 SPOOLing 实现。

SPOOLing 技术利用外存把独占设备改造成共享设备。系统在磁盘上开辟输入井和输出井，输入井存放预先读入的数据，输出井存放将要输出到设备的数据，井是磁盘上的存储区域，用来暂存作业的输入输出数据。预输入程序在作业执行前把数据送入输入井，缓输出程序在设备空闲时把输出井中的数据送出。多个进程可同时把请求排入井中，由系统统一调度设备，独占的打印机就被虚拟成可共享的设备。实现 SPOOLing 需要多道程序设计技术使 CPU 与 I/O 并行，还需要大容量外存提供井的空间。

一次读操作的处理过程如下。用户程序调用 read 函数，陷入内核，系统调用入口把参数交给设备独立性软件；设备独立性软件把逻辑设备名映射为物理设备，分配缓冲区，调用相应设备的驱动程序；驱动程序把读命令、内存地址和传送长度写入控制器的控制寄存器和数据寄存器，启动设备并阻塞当前进程；设备完成传送后发出中断，中断处理程序保存现场并唤醒驱动程序；驱动程序检查状态，把数据取到内核缓冲区；系统调用返回，数据送到用户缓冲区，进程恢复运行。

从处理流程可以看出 I/O 软件各层的分工。用户层负责提供接口和格式转换，设备独立性软件负责与设备无关的公共管理，驱动程序负责硬件操作，中断处理程序负责事件响应。分层使每层只关注自己的职责，下层的变化不影响上层，新增设备时只需编写相应的驱动程序。I/O 请求自顶向下逐层转换，从抽象的文件操作变为具体的寄存器操作，完成后再自底向上返回。
