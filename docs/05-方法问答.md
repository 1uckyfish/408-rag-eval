# 05 方法问答（三层追问）

> 规则：每题先背 20 秒版本，再准备一句"要展开我可以讲……"。**答不上来的，回去补实验，不是背表述。**
> 所有数字必须能对上 `docs/04-实验记录.md` 和 `results/*.csv`；对不上就说"我记的是约数"，别编。

## 0. 先背这 9 个数字（记不住就别说）

| 项 | 数字 |
|---|---|
| 语料 | **36 篇 / 306 段 / 6.8 万字**（按 408 大纲自撰，规避教材版权） |

| 默认配置 | 512/0：recall@5 **0.8486**、recall@1 **0.5389**、P95 约 1.5ms |
| 网格最好 | 1024/64：recall@5 **0.9292**（但 recall@1 只有 0.5111） |
| dense 单点 | 512/0：recall@5 **0.7640**、MRR 0.5730、P95 十几~几十 ms |
| 失败分桶 | A（完全没召回）**16** / B（召回到没排第一）**37** / C 4 |
| 标注一致率 | 隔日盲标 20 条：严格一致 **40%**，有重叠 50%，Jaccard 0.433 |
| 复现 | 干净 clone 三条命令 **1s / 5s / 3s**，指标逐项一致、延迟差 3.3 倍 |

## 第一层：这项目是干什么的

**Q1 一句话介绍**
> "一个检索策略的**评测台**，不是问答产品：用 195 道 408 真题（其中 159 道改写成 120 条检索式 query），配 36 篇按大纲整理的语料，跑 8 组 chunk 配置，回答'切多大、要不要换向量检索、瓶颈在召回还是在排序'。"
>
> 展开：所有结论在 `results/` 的 CSV 和 5 张图里，界面只是外壳——`ask.py` 和 Streamlit 页都不产生新结论。

**Q2 为什么不做知识库问答产品**
> "产品形态谁都能搭，**评测才是分水岭**。而且我这个项目里最有价值的一句话是'BM25 在这个场景赢了 dense 8 个点'——这是产品做出来也不会知道的。"

**Q3 这跟 408 有什么关系**
> "评测集就是 408 真题，语料是操作系统知识。它同时是我的复习工具：检索不到的题，就是我的知识盲区。比如 q050 那条'连续取 10 件'，语料里根本没有批量消费的段落。"

## 第二层：方法是否站得住

**Q4 chunk 怎么切的？**
> "零依赖自己写的滑窗：按字符切，切点回退到 **`lo = start + size//2` 到 `hi = end + size//4` 窗口内最近的句末标点**（。！？；换行），保证不把一句话劈开；overlap 从上一块尾部取固定 64 字符。"
>
> 展开：**不用 LangChain 的 RecursiveCharacterTextSplitter**，因为它的分隔符回退顺序在我的语料上会把表格和公式切碎，而且我说不清"到底是我的参数起作用还是它默认值起作用"。

**Q5 为什么选 512，不是 1024？**
> "因为 **recall@5 会骗人**。1024/64 的 recall@5 是 0.9292，比 512/0 的 0.8486 高 8.1 个点——但 chunk 总数从 591 掉到 93，top-5 占全库比例从 0.8% 涨到 5.4%，分母小了自然容易中。换成更严的 **recall@1，512 见顶 0.5389，1024 两档都回落（0.5069 / 0.5111）**。"
>
> 补一句：这就是我加图 4 的原因——**报一个指标会得出相反结论**。

**Q6 overlap=64 有用吗？**
> "方向上是正的，但**幅度不够下结论**。512 上加 64 是 0.8486 → 0.8792（+3.1 个点），128 上是 0.5653 → 0.6014（+3.6 个点）。120 条 query 里一条约 0.83 个点，3.1 点相当于 **3–4 道题**。"
>
> 诚实版："所以我说'方向一致，但样本量不支持做显著性检验'。有意思的是，语料从 18 篇扩到 36 篇之后，128 上的 overlap 从 **−2.4 点翻成 +3.6 点**——说明这个效应本身不稳。"

**Q7 dense 为什么输给 BM25？**
> "三个数：recall@5 **0.7640 vs 0.8486**、MRR **0.5730 vs 0.6968**、P95 **几十 ms vs 1.5ms**——**又慢十倍又更不准**。"
>
> 原因两条：① query 是术语密集的短句（"页表项 2B、页大小 2^10B 时页目录最少多少项"），字符 bigram 恰好精确命中术语；② 语料是我按考点写的，和 query 同源，语义向量的"泛化优势"用不上。**换真实用户长问句这个结论未必成立**，这是我主动写进 README 的局限。

**Q8 gold 谁标的？可靠吗？**
> "我自己标，规则是'只给这一段，能不能答完整这道题'。可靠性做了**隔日盲标 20 条**：严格一致 **40%**、有重叠 50%、平均 Jaccard **0.433**。"
>
> 关键补充："40% 听着低，但要分两类：12 条不一致里 **8 条是'两个都对的段之间换选择'**，4 条是真分歧。而且我算了影响——同样这 20 条，recall@5 只差 **2.5 个点**（主结论稳），**MRR 差 16.7 个点**（所以对外只讲 recall@5）。"
>
> 加分句："抽检还查出我一条真错标（q050，把有界缓冲套到批量消费上），这条我写进 `docs/06` 了。"

**Q9 120 条够吗？**
> "够做**配置间的相对比较**（配对设计，同题同 gold），不够做绝对性能声明。所以我从头到尾只说'相对提升'，没说'达到 SOTA'，也没做显著性检验——我用的是逐题差值分布，1024/64 相对 512/0 是**涨 15 条、跌 1 条、不变 104 条**，我直接告诉你这 8.9 点全来自 15 道题。"

**Q10 延迟怎么测的？**
> "warmup 后测 30 次取 P95，因为均值会被个别慢请求掩盖。**但我要主动说一个坑**：同机同代码，冷启动复现时 128/0 的 P95 是 **2.81ms**，我原来记的是 **9.38ms**，差 3.3 倍——延迟受机器负载影响太大，所以我现在只讲量级（个位数 ms 对十几 ms），不讲小数。"

**Q11 为什么用 recall 不用 precision？**
> "检索的下游是 LLM，多给几条不致命、漏掉才致命，所以召回优先。但我也承认 recall 的边界：**它不看位置**，所以我才补了 recall@1 和 MRR 来看排序质量。"

## 第三层：边界、失败、反思

**Q12 结果不显著怎么办？**
> "已经遇到了，也处理了。overlap 只 +3.9 点、编号噪声消融只 +0.83 点（恰好翻 1 条题），我都**按'方向一致但幅度不足'写**，没有硬说成结论。真正的结论只留了三个：512 是合理档位、BM25 不换、瓶颈在排序。"

**Q13 rerank 值不值？**
> "**没做，这是我知道的最大缺口**。但我把'值不值得做'的前置证据做出来了：120 条里 **37 条是召回到了却没排第一**，只有 16 条完全没召回——**瓶颈在排序不在召回**，所以 rerank 有立项价值。"
>
> 展开："之所以砍掉，是 3 周版的时间约束；相比之下'证明瓶颈在哪'比'跑一个 rerank 得一个数'更值。"

**Q14 如果重做，你会改什么？**
> "三件：① query 扩到 300+ 并做**双人独立标注**（现在只有我自己 + 模型盲标）；② 补 rerank 单点，把 Q3 从'立项依据'变成'结论'；③ 语料换成真教材原文，验证'自撰语料让 BM25 偏乐观'这个怀疑。"

**Q15 你的数据和公开 benchmark 有什么不同？**
> "领域特定：术语密集、答案集中在 1–2 段、query 短（平均 53 字）。MTEB 这类通用检索 benchmark 不覆盖这种分布——它们测的是开放域语义匹配，我这里测的是**术语精确匹配 + 段落定位**。这也是 BM25 能赢的结构性原因。"

## 自测（讲之前先过这三关）

1. **数字关**：上面 9 个数字，随机抽 3 个能立刻说出来；
2. **反问关**：每个结论都要能答"你怎么知道不是语料太小造成的"——答案是 recall@1 拐点 + 逐题差值分布；
3. **诚实关**：主动说出三条软肋（延迟不可复现、语料自撰、一致率 40%），**说在面试官问之前**。
