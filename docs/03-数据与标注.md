# 03 数据与标注

## 1. 语料（corpus）

**用什么**：你自己的操作系统笔记 / 教材章节整理稿 / 课程 PPT 转成的 md。每篇 800–3000 字，**一篇对应一个章节**（便于按章节分析失败案例）。

**不要**：直接把整本 PDF 丢进去。页眉、页码、公式乱码会严重污染检索，而且你没法解释"为什么这段是垃圾"。

**格式**：`data/corpus/<章节>.md`，纯文本，段落之间空一行（切分器按空行识别段落）。

**版权**：教材原文只在本机使用，`data/corpus/` 加进 `.gitignore`；公开仓库只放你**自己写的**笔记摘要和标注文件。

## 2. Query 集（200 条）

来源：408 历年真题（2009–2024）操作系统部分。

**改写规则**（很重要，决定实验是否公平）：
1. 去掉选项 A/B/C/D，只留题干。
2. 去掉"下列说法正确的是"这类无信息量前缀。
3. 保留术语原文（"页表""TLB""时间片"），不要改写成口语——否则你测的是改写能力，不是检索能力。
4. 大题拆成可检索的小问。

**为什么不直接用教材课后题**：真题有标准答案，且分布真实；课后题和教材正文措辞太像，会导致 recall 虚高。

## 3. Gold 段落标注

对每条 query，在语料里标 1–3 个"能回答这个问题"的段落。

- 标 **para 序号**（从 0 开始，按空行分隔的顺序），不标字符位置——这样换 chunk 大小不影响标注。
- 标注时间预算：**每题 30 秒**，200 题 ≈ 100 分钟，分两次做完。
- 判断题："如果只给读者这一段，他能答出这题吗？"能 → 标；不能 → 不标。
- 允许标 2–3 段（答案分散时），这样 recall 才有区分度。

**一致性抽检**：隔一天，随机抽 20 条重标，算"两次标注的重合率"。≥85% 就写进实验记录；低于就说明标准不清，先统一标准再继续。

## 4. 数据格式

`data/queries.jsonl`，一行一条：

```json
{"qid":"q001","query":"进程和线程的区别是什么","gold":[{"doc":"os-03","para":7}],"type":"概念","year":2016}
```

字段说明：
- `qid`：唯一 id，别改（结果 CSV 用它对齐）
- `query`：检索用的文本
- `gold`：段落列表，`doc` 是 `data/corpus/xxx.md` 的文件名（不含扩展名）
- `type`：概念 / 计算 / 综合，用于分层分析
- `year`：真题年份（可选，用于"新题是否更难"的分析）

## 5. 示例数据

语料 `data/corpus/os-01.md … os-15.md` 共 15 篇、约 2.7 万字、137 段，按 408 大纲分章撰写（每篇 1000–1800 字，段间空一行）。旧的 `os-001.md`、`os-002.md` 两篇示例语料在正式语料到位后已删除。

判断语料是否合格：

```
py -3 src\check_corpus.py --min-files 15
```

它查字数区间、段数、段长、Markdown 残留、禁用语、跨文件重复段落，并打印每篇的字数与段数。

## 6. 常见坑

| 坑 | 现象 | 解法 |
|---|---|---|
| gold 标在 chunk 上 | 换 size 后 recall 全乱 | 一律标段落 |
| 一问多答只标一段 | recall 天花板只有 0.5 | 标全 1–3 段 |
| 语料有重复段 | recall 虚高 | 建索引前去重（按段落 hash） |
| query 含选项 | 检索被 "A." "B." 干扰 | 去掉选项 |
| 页眉混入 | 每篇开头都有"第 3 章 内存管理" | 清洗时删掉重复行 |
