# 08 真题收集与转录（W1-D2 的操作手册）

> 目标：`data/raw/exam.md` 里攒够 **≥150 道** 408 操作系统真题（选择题 + 综合题），
> 每题带**答案**和**一句解析**，供 D3–D4 改写成检索式 query。

## 1. 先认清一个事实：这些 PDF 没有文字层

`data/raw/pdf/*.pdf` 是扫描件，字体是内嵌子集且没有 ToUnicode 表。实测：

```powershell
py -3 -c "import pymupdf; print(pymupdf.open(r'data/raw/pdf/2009.pdf')[0].get_text()[:50])"
# 输出是 '\xc4\xe3...' 之类的乱码，按 gb18030/big5 重解码也救不回来
```

所以**不要**走"PDF 提文字 → 正则清洗"的路（试过一次，白费 20 分钟）。
正确姿势：**渲染成 PNG，逐页读图抄录**。视觉模型读扫描件比任何 OCR 管线都准，
而且能顺手把"答案 + 为什么"一起写下来。

## 2. 三条命令

```powershell
# ① 下载当年真题（GitHub Pages 直链，实测 ~12KB/s，1.3MB 的卷子约 2 分钟）
curl.exe -sS -L -o data\raw\pdf\2015.pdf `
  "https://lucas2029460802.github.io/myblog/files/408/2009-2021%E7%9C%9F%E9%A2%98/2015%E7%9C%9F%E9%A2%98.pdf"

# ② 渲染成图（默认 140dpi，够清楚又不至于太大）
py -3 src\render_exam.py --pdf data\raw\pdf\2015.pdf

# ③ 校验结构和题量（--min 150 时不达标退出码非 0）
py -3 src\check_exam.py --min 150
```

> 2022–2024 的卷子是"真题+答案"合订本，单个 14MB，按 12KB/s 要 20 分钟一份；
> 2009–2021 的单独卷子都只有 1.3MB 左右。**先做 2009–2021，够 150 题**，近年卷子有空再补。

## 3. 卷面版式（省时间的关键）

408 卷面结构 16 年基本没变：

| 部分 | 题号 | 说明 |
|---|---|---|
| 单项选择题 | 1–40 | 数据结构 1–10、组成 11–22、**操作系统 23–32**、网络 33–40 |
| 综合应用题 | 41–47 | 数据结构 1 题、组成 1–2 题、**操作系统 2 题（通常 45、46）**、网络 1 题 |

所以每个 PDF 只需要看 **4 页左右**：第 3–4 页（23–32 题）+ 第 6–7 页（45、46 题）。
`2009` 是 7 页卷（选择 23–32 在第 3–4 页，综合 45、46 在第 6 页）；`2010` 是 8 页卷（同理）。
个别年份题号会漂（比如某年 OS 只出 9 道选择），**以题干里的"操作系统"术语为准，不要死认题号**。

## 4. 转录格式（`data/raw/exam.md`）

```markdown
## 2015

### 2015-23
- 题型: 选择
- 考点: 进程/调度算法
- 难度: 易
- 题干: 下列选项中，…____。
- 选项A: …
- 选项B: …
- 选项C: …
- 选项D: …
- 答案: B
- 解析: 一句话说清为什么，以及最容易错在哪。
```

硬性要求（`src/check_exam.py` 会查）：

1. `### <年份>-<原题号>`，题号用卷面原号（23–32、45、46），**不要自己重排**；
2. `题型` 只能是 `选择`/`综合`；选择题必须有 `选项A`–`选项D` 和 `答案`（单个字母）；
3. 综合题用 `参考答案:`（可多行，缩进续行），不要硬凑成选择题格式；
4. `考点` 写成 `章/考点`，章只能是 `概述`/`进程`/`内存`/`文件`/`IO` 之一——这五个是 408 大纲的五章，W3 的分层分析直接按它切；
5. `难度` 取 `易`/`中`/`难`，主观判断即可，用于"难题是否更难检索"的分析；
6. 题干里**保留原术语**（页表、TLB、时间片），把图/表用文字转述清楚（"磁头位于 100 号磁道，向磁道号增大方向移动"），因为 D3 改写 query 时只能依赖文字；
7. 选项里的罗马数字用 Ⅰ Ⅱ Ⅲ Ⅳ，与原文一致，避免和字母 A/B/C/D 混淆。

**来源标注**：扫描件抄来的不写 `来源`；凭记忆补的题必须写 `- 来源: 记忆重建（年份/题号待核）`，
D5 抽检时优先核这些。文件名一致、题号连续的，默认视为扫描件转录。

## 5. 每题 60–90 秒的抄录节奏

1. 读图，只抄 23–32 和 45、46；
2. 先写题干和四个选项（**照抄，不润色**）；
3. 立刻写答案——选择题当场推一遍，综合题写关键步骤和最终数值；
4. `解析` 只写"采分点/易错点"一句到两句，不要写成长篇题解（那是 D3 之后的事）。

两个年份 ≈ 24 题 ≈ 半小时。**一天做完 2009–2021 是现实的**（约 150 题，分 3 次，每次 4 年）。

## 6. 进度与验收

| 项 | 标准 | 当前（2026-11-04 收工） |
|---|---|---|
| 题量 | ≥150（W1-D2 验收线） | **159 题（2009–2021，13 个年份全覆盖）** |
| 结构 | `check_exam.py` 零问题 | ✅ 通过（`--min 150` 退出码 0） |
| 覆盖率 | 五章都有，进程/内存各 ≥30 | 进程 57、内存 36、文件 30、概述 19、IO 17 |
| 题型 | 选择 + 综合都要有 | 选择 130、综合 29 |

> 章节配比目标（150 题）：概述 ~15、进程 ~50、内存 ~40、文件 ~25、IO ~25。
> 进程和内存是 408 OS 的大头，也是 recall 最容易出区分度的地方，别偷懒少抄。
>
> 实际结果：进程 57 / 内存 36 / 文件 30 / 概述 19 / IO 17。IO 比目标少 8 题、内存少 4 题，
> 不影响主线结论，但 W2 若发现 IO 类 query 的 recall 异常，先想到"样本少"而不是"检索差"。
> 2016、2018、2021 各多收 1 道综合题（那三年 OS 综合占了 3 道），所以是 13 年 159 题而不是 156 题。

### 6.1 各年题号与素材位置

| 年份 | 选择题 | OS 综合题 | PDF/PNG 位置 |
|---|---|---|---|

> 题号不是每年都固定在 45/46：2014 的 45 是组成题、2019 的 43/44 才是 OS、2018 从 44 起。
> 这也是"先看第 3 页确认 OS 从第几题开始"这条规矩的由来。
> 2022–2024 是"真题+答案"合订本（单份 14MB），尚未收；要补的话放在 2026-11-22 之后。

### 6.2 合并脚本

转录阶段可以让多个 agent 各写一份 `data/raw/_parts/<年份段>.md`，最后：

```powershell
py -3 src\merge_parts.py            # 按 (年份, 题号) 去重排序后整体重写 exam.md
py -3 src\merge_parts.py --dry-run  # 只看会合并多少题
py -3 src\check_exam.py --min 150
```

`merge_parts.py` 会丢弃 `## 年份` 分隔行并重新生成，所以分片文件里的年份标记重复也无所谓。
