# 00 选题与定位

## 1. 为什么是 C（RAG 评测），不是 B（shell + 测量）

两个方案的差别不在难度，在**能不能被追问三层**。

| 维度 | B（shell+测量） | C（RAG 评测） |
|---|---|---|
| 上手门槛 | 低 | 中（环境 + 领域知识） |
| 8 周做完概率 | 95% | 70% |
| 金钱成本 | 0 | 0–200 元 |
| 稀缺性 | 低 | 高 |
| 与 408 协同 | 强 | 弱 |
| 与 AI 导师相关性 | 弱 | 强 |
| 被追问三层后 | 靠测量章节 | 靠实验设计和统计 |
| 最大风险 | 同质化，被当成复刻 | 结果不显著 / 被当成调包 |

**共同点**：救赎都在"测量"。B 测的是内核行为，C 测的是检索质量。真正决定答辩表现的不是选题，是**有没有留下自己产生的数据**。

选 C 的代价要认：要花两周折腾环境、结论可能不显著、还要花点 API 钱。换来的是稀缺性和与 AI 方向的相关性。

## 2. 项目叙事（30 秒讲完 · 2026-11-11 实测版）

> "我备考 408，发现市面上的 RAG demo 都在讲'我搭了个知识库问答'，但没人回答'chunk 该切多大'。
> 我就把 2009–2024 的 195 道 408 真题（其中 159 道改写成 120 条检索式 query），配 36 篇按大纲整理的语料，跑了 4×2 共 8 组 chunk 配置。
> 结论有三个：**第一，512 就是该选的档位**——1024 的 recall@5 更高，但那是 chunk 只剩 93 块、分母变小的假象，换成 recall@1 它就掉下来了；
> **第二，这个场景 BM25 赢了向量检索**：recall@5 高 8 个点、快 10 倍，因为 408 的 query 是术语密集的短句；
> **第三，瓶颈在排序不在召回**：120 条里 37 条是'召回到了但没排第一'，只有 16 条完全没召回，所以 rerank 值得做，我这次因为时间砍了。
> 代码在 GitHub 上，三条命令能复现，指标逐项一致。"

这段话里每一句都能被追问，每句都有对应实验（见 `docs/05`）。**不要说"我做了 rerank"——没做，说了会被问穿。**

## 3. 三种结局的预案（现在就写好，别到时候慌）

### 结局 A：网格出现明显最优（理想）
- 交付：热力图 + 帕累托 + 结论句。
- 强化：补统计检验（配对 bootstrap CI），说"差异显著，p<0.05"。

### 结局 B：各配置差别很小（很常见）　← **实测落在这里**
不要硬编故事。改讲：
- "在这类**短查询 + 术语密集**的语料上，chunk 大小的影响被 BM25 的精确匹配掩盖了"——然后给证据：按题型（概念/计算/综合）、按 query 长度分组看差异。
- 这反而是更成熟的结论：**"chunk 大小不是瓶颈，排序才是"**。实测证据就是失败分桶：37 条"召回到没排第一" vs 16 条"完全没召回"。
- 落地版三句话：512 合理（1024 的高 recall 是分母假象）→ BM25 不换（快 10 倍还高 8 点）→ 瓶颈在排序（rerank 有立项价值，但这次没做）。

### 结局 C：环境/预算失败
- 全本地化：bge-small-zh（~100MB）+ BM25，0 元。
- 若连模型都下不动：只做 BM25 的 chunk 网格，仍是一个完整项目（只是叙事弱一档）。

## 4. 不要做的事

- ❌ 不要做成"聊天界面 + 知识库"的 demo（那就是被当成复刻的典型）。
- ❌ 不要用 LangChain 的 `RecursiveCharacterTextSplitter` 当核心卖点（老师会问"它的边界规则是什么"，答不上就穿帮）。切分自己写，20 行。
- ❌ 不要只报平均值。要报 **P95 延迟**、要报 **CI**、要报 **失败案例**。
- ❌ 不要堆 20 个 embedding 模型。3 个足够，深度 > 广度。
