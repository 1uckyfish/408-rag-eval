# 02 技术方案

> 定位：这是**方案稿**（当初怎么设计的），不是结果。文中"（已做）／（未做）"按 2026-11-11 实际状态标注，一切数字以 `docs/04-实验记录.md` 为准。

## 1. 架构

```
408 真题 ──► query 集（120 条，人工标 gold 段落）
                │
自撰语料 ──► 切分器 ──► chunk 集 ──► 索引 ──► 检索 top-k ──► 指标
             (size,overlap)        BM25 / dense         recall@k
                                                          MRR@10
                                                          nDCG@10
                                                          P95 latency
```

**关键点：gold 标在"段落"上，不标在 chunk 上。** 因为 chunk 大小是自变量，如果 gold 跟着 chunk 走，实验就循环论证了。判定规则：检索到的 chunk 若覆盖 gold 段落的中点，算命中。

## 2. 自变量（网格）

| 变量 | 取值 | 说明 |
|---|---|---|
| chunk_size | 128 / 256 / 512 / 1024（字符） | 中文按字符近似 token；1 token ≈ 1.5 汉字，512 字符 ≈ 340 token |
| overlap | 0 / 64 | 相对 size 的 12.5%–25% 是常见区间 |
| retriever | bm25 / bge-small-zh-v1.5（已做，只做 512 与 256 两个单点） | bge-m3（未做，3 周版砍） |
| rerank | bge-reranker-base（未做，3 周版砍） | 只对 top-20 重排再取 top-5；现在只有"瓶颈在排序"的立项依据 |

## 3. 因变量（指标）

- **recall@k** = 命中的 gold 段落数 / 该题 gold 段落总数，对 query 取平均。k=5 为主；另外补报 recall@1、recall@3（见 `results/grid_recall_k.csv`）。
- **MRR@10** = 第一个命中位置的倒数的平均。注意：gold 多为单段时 MRR 会系统性偏低（一致率抽检里 MRR 差 16.7pt），**对外只讲 recall@5**。
- **nDCG@10**：二值相关性（命中=1），用于对"命中在第几位"更敏感。
- **P95 延迟**：单次 query 的端到端耗时（含检索，不含生成），warmup 3 次后测 30 次取 P95。**实测不可复现**：同机同代码两次跑差 3.3 倍（2.81ms vs 9.38ms），只报量级。

## 4. 控制变量（写进 README，否则结论不可信）

1. 同一份语料、同一份 query、同一台机器。
2. 同一分词方式（BM25 用字符 bigram，中文不分词也能打）。
3. 随机种子固定；dense 检索若用 HNSW，ef 固定。
4. 延迟测量关掉其他大程序；每配置重复 3 次取中位数。
5. 报告时同时给均值和波动范围（**未用 CI**，见第 5 节实际做法）。

## 5. 统计方法（实际只做了第 3 条）

- **配对 bootstrap**（未做）：对逐题得分有放回重采样 1000 次，得到 (最优 − 默认) 差值的 95% CI。CI 不含 0 才能说"显著"。
- Friedman + Nemenyi（未做）。
- **实际做法**：直接给**逐题差值分布**（`results/fig5_delta_distribution.png`）——1024/64 相对 512/0 是"涨 15 条 / 跌 1 条 / 不变 104 条"，并说明这 +8.9pt 全部来自 15 条题、稳定性弱。120 条样本下不做显著性检验，只做"方向 + 幅度 + 集中度"的描述，面试时主动说明这一点比硬套 p 值更稳。
- 不要用 t 检验硬套（recall 是比例，不是正态）。

## 7. 扩展点（有余力再做，别一开始就做）

- **混合检索**：BM25 + dense 分数加权（RRF），通常比单一检索强，是一个容易出彩的对比。
- **查询改写**：把口语 query 改写成术语 query，看 recall 变化。
- **分块语义化**：按标题/段落切 vs 定长切，验证"语义切分是否真的更好"。

## 8. 复现命令（实际形态，详见 README §7）

```powershell
# 0. 校验数据（约 1s）
py -3 src\check_corpus.py --min-files 36

# 1. 建索引 + 跑 8 组网格（约 5s）→ results/grid_bm25.csv
py -3 src\run_grid.py

# 2. 出图 0–3（约 3s）；图 4、图 5 另跑 plot_recall1.py / plot_delta.py
py -3 src\plot_figures.py
```

注：`run_grid.py` 支持 `--corpus / --queries / --sizes / --overlaps / --k / --out`，默认值就是正式配置（4 档 size × 2 档 overlap、k=5、写 `results/grid_bm25.csv`），所以裸跑即可。
