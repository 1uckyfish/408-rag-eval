## 2026-11-10 引用式回答（`ask.py --cite`）

- **chunk 跨多段时引哪一段**：512 字 chunk 常覆盖 2–3 段，用"与问题的词重合数"挑最贴合的段再引（`best_para()`），避免笼统地标"第 0–2 段"。
- **其他候选必须带段号**：只显示篇号时"os-06（17.2）、os-06（10.2）"看不出差别。
- **故意不接 LLM**：一接生成，评测对象从"检索策略"变成"生成质量"，8 组网格 / recall@5 / MRR 全部失去意义。被问"为什么不是问答机器人"就答这条。
- **演示坑（诚实说法）**：问"页表项 2B、页大小 2^10B 时页目录最少多少项"，检索返回 os-27 第 3 段的四级页表推导——语料里没有 2B/2^10 这个组合的完整推导（只有 4B/4KB 的 1024 项版本）。这是语料缺口，不是程序 bug，正好印证"语料自撰、覆盖不全"的局限。现场演示用"死锁四个必要条件""进程和线程区别"这类答得完整的题。

## 2026-11-10 标注一致性抽检

- 做法：分层抽 20 条（概念 9 / 计算 7 / 综合 4，种子 20261109），**藏掉答案**后由独立子代理重标；首标当初是借 BM25 top-5 候选标的。
- 数字：严格一致 **8/20 = 40%**、有重叠 50%、平均 Jaccard 0.433。
- 12 条不一致里 8 条是"两个都对的段之间换选择"，4 条真分歧（q031/q043/q059/q050，q050 首标标错：把有界缓冲硬套到"连续取 10 件"的题上）。
- **换成重标 gold 后的指标**（同 20 条，512/0）：首标 0.850 / 0.608 / 0.662；重标 0.825 / 0.592 / 0.628；并集 **0.867 / 0.775 / 0.740**。
- 结论口径：recall@5 只差 2.5pt → 主结论稳健；MRR 差 16.7pt → 单段 gold 会系统性低估排序质量，**对外只讲 recall@5**。
- 必须主动说的局限：这轮重标者是模型，"human agreement"仍缺；要补就是你本人拿 `data/raw/_relabel/round1.md` 再标一遍。

## 2026-11-10 Streamlit 演示页

- 定位一句话：**外壳，不产结论**。页面只把 `ask.py --cite` 的结果画成卡片，离线可复现的结论仍只认 `results/*.csv` 与 `docs/04`。
- 依赖隔离：核心 BM25 链零依赖这条不能破，所以装进 `.venv` 并单独写 `requirements-demo.txt`（streamlit 1.67.0 / pandas 3.1.1 / pyarrow 26.0.1，约 60MB）。被问"为什么引入重依赖"就答这条。
- 实现要点：`@st.cache_resource` 缓存索引（否则每次调参都重建，128/64 要 0.5s，交互会卡）；侧栏指标直接从 `grid_bm25.csv` + `grid_recall_k.csv` 读，**读不到就显示"—"，不编数**；引用卡片沿用 `best_para()` 的"词重合挑段"逻辑，和命令行一致。
- 验证方式：`streamlit.testing.v1.AppTest` 无头跑，断言无 exception、输入问题后出现 success 卡片与 expander、侧栏指标为 0.8403/0.5264/160。这比"打开浏览器看一眼"更适合留证。

## 2026-11-11 冷启动复现（面试高频：别人能跑吗）

- 做法：`git clone` 到干净目录，**只用系统 Python**、不带 `.venv`、不带本地缓存，照 README 跑。三条命令 1s / 5s / 3s 全绿。
- 判据措辞：**"指标可复现，延迟不可复现"**。`grid_bm25.csv` 的 chunks/recall/MRR/nDCG 逐项一致（512/0 = 0.8403、1024/64 = 0.9292）。
- **P95 差 3.3 倍**：同机同代码，128/0 冷启动实测 2.81ms vs 原记录 9.38ms（受当时负载影响）。对外只讲"个位数 ms 对十几 ms"的量级差，不讲具体小数——正好呼应"别把 CPU 单机延迟说成系统性能"这条丢分项。
- 查出两个**只有冷启动才会暴露**的仓库错误：
  1. `data/corpus/` 被 `.gitignore` 排除 → clone 后 `FileNotFoundError: 'data/corpus'`，三条命令全挂。已让语料入库（自撰、不涉版权）。
  2. `data/cache/*.npy`（16MB embedding 缓存）反而被提交 → 已 `git rm --cached` 并忽略。
- 说明口径：`data/raw/`（真题 PDF 与 exam.md）**故意不入库**（原卷版权），干净 clone 里 `check_exam.py` 报"找不到 data/raw/exam.md"是**预期行为**；评测不依赖它，因为派生的 `queries.jsonl` 已入库。
